# Design: setup-crmsdk Project Hardening & Enhancement (v1.3.0)

Generated by CEO Plan Review on 2026-03-18
Branch: main | Mode: SELECTIVE EXPANSION

## Summary

This design captures the accepted scope for the next release of setup-crmsdk (v1.3.0), focused on supply chain hardening, performance (caching), resilience (retry), and developer experience (richer outputs, input validation).

## Vision

### 10x Check

The 10x version is "setup-dynamics365-tools" -- a comprehensive CI toolchain installer supporting both CrmSdk.CoreTools and pac CLI, with built-in caching, supply chain verification, version management, and rich action outputs. The "setup-node" equivalent for Dynamics 365 development.

This plan implements the foundation for that vision.

## Accepted Scope (v1.3.0)

| # | Feature | Effort (CC) | Description |
|---|---------|-------------|-------------|
| 1 | SDK Caching | S | Cache installed SDK using actions/cache in action.yml, keyed by version + OS |
| 2 | NuGet CLI Supply Chain Hardening | S | Pin NuGet CLI to specific version with SHA256 checksum verification |
| 3 | Download Retry Logic | S | Retry with exponential backoff for NuGet CLI download and package install |
| 4 | Richer Action Outputs | S | Add sdk-version, cache-hit, and tool-path outputs to action.yml |
| 5 | Version Input Validation | S | Validate version input format before attempting NuGet install |
| 6 | Stale CRM_SDK_PATH Fix | S | Verify path exists when CRM_SDK_PATH is set; re-install if directory is missing |
| 7 | GITHUB_ENV Error Handling | S | Wrap GITHUB_ENV file write in Invoke-Safely with descriptive error message |

## Architecture

### Current Flow

```
action.yml (1 step) --> Install-CrmSdk.ps1 --> Install-CrmSdk.psm1
```

### Proposed Flow

```
action.yml (4 steps):
  1. Validate version input
  2. Restore cache (actions/cache)
  3. Install CRM SDK (existing script, enhanced)
  4. Save cache (actions/cache)
```

### Cache Key Strategy

```
Key: crmsdk-{version|'latest'}-{runner.os}
Restore keys: crmsdk-{version|'latest'}-
```

## Key Decisions

1. **Caching approach:** actions/cache in action.yml (not PowerShell-native). Standard GitHub Actions pattern.
2. **Strategic direction:** Going concern. This action serves teams still on CrmSdk.CoreTools.
3. **pac CLI:** Deferred to TODOS.md as a separate initiative requiring its own design.

## Testing Requirements

New tests needed for: version validation, checksum verification, retry logic (success on attempt 2, all attempts fail), stale CRM_SDK_PATH, and GITHUB_ENV error handling. Estimated ~15-20 new test cases.
